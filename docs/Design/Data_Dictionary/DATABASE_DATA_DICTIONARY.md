# قاموس البيانات (Data Dictionary)

يوثق قاموس البيانات بنية المعلومات المستخدمة في النظام وصفاتها وقواعدها، ويعمل مرجعاً موحداً للمطورين عند تصميم قاعدة البيانات وتنفيذها واستخدامها.

## الغرض

- توضيح أسماء الجداول والحقول بدقة.
- تحديد أنواع البيانات وأطوالها وقيودها.
- توضيح القيم المطلوبة والاختيارية والقيم الافتراضية.
- توضيح المفاتيح الأساسية والأجنبية وعلاقات البيانات.

## مكونات التوثيق

تتكون قاعدة البيانات الموضحة في مخطط ERD من ثلاثة جداول رئيسية لإدارة بيانات المستخدمين، وصلاحيات المشرفين، وجلسات تسجيل الدخول.

## نظرة عامة على بنية قاعدة البيانات والعلاقات

- **Users – Sessions:** علاقة رأس بأطراف (One-to-Many | 1:N) عبر المفتاح الأجنبي `Sessions.user_id` المرتبط بالمفتاح الأساسي `Users.id`. يمكن للمستخدم الواحد امتلاك عدة جلسات تسجيل دخول.
- **Users – Admins:** علاقة رأس برأس (One-to-One | 1:1) عبر المفتاح الأجنبي `Admins.user_id` المرتبط بالمفتاح الأساسي `Users.id`. يحدد هذا الربط حساب المستخدم الذي يملك صلاحيات المشرف، ويُشار إلى القيد باسم `fk_Admins_user_id_Users`.

## جدول المستخدمين (Users)

يخزن هذا الجدول البيانات الأساسية لحسابات المستخدمين المسجلين في النظام وبيانات الاعتماد الخاصة بهم.

| اسم الحقل | نوع البيانات | القيود والمفاتيح | يقبل فارغاً؟ | الوصف الوظيفي |
|---|---|---|---|---|
| id | INTEGER | مفتاح أساسي (PK)، يُنشأ تلقائياً | لا (NOT NULL) | المعرف الرقمي الفريد للمستخدم. |
| full_name | VARCHAR(255) | - | لا (NOT NULL) | الاسم الكامل للمستخدم. |
| username | VARCHAR(100) | UNIQUE | لا (NOT NULL) | اسم المستخدم الفريد الذي يُستخدم لتسجيل الدخول أو العرض. |
| email | VARCHAR(255) | UNIQUE | لا (NOT NULL) | البريد الإلكتروني الخاص بالمستخدم ويجب ألا يتكرر. |
| password_hash | VARCHAR(255) | - | لا (NOT NULL) | تجزئة كلمة مرور المستخدم المشفرة لحمايتها وعدم تخزينها بصيغتها الأصلية. |
| created_at | TIMESTAMP | - | لا (NOT NULL) | تاريخ ووقت إنشاء حساب المستخدم. |

## جدول الجلسات (Sessions)

يدير هذا الجدول جلسات تسجيل الدخول النشطة والمنتهية للمستخدمين ورموز التحقق الخاصة بكل جلسة.

| اسم الحقل | نوع البيانات | القيود والمفاتيح | يقبل فارغاً؟ | الوصف الوظيفي |
|---|---|---|---|---|
| id | INTEGER | مفتاح أساسي (PK)، يُنشأ تلقائياً | لا (NOT NULL) | المعرف الرقمي الفريد للجلسة. |
| user_id | INTEGER | مفتاح خارجي (FK) يشير إلى `Users(id)` | لا (NOT NULL) | يربط الجلسة بالمستخدم صاحب الجلسة. |
| token_hash | VARCHAR(255) | - | لا (NOT NULL) | تجزئة رمز الجلسة المستخدمة للتحقق من هوية الجلسة دون تخزين رمزها الأصلي. |
| created_at | TIMESTAMP | - | لا (NOT NULL) | تاريخ ووقت بدء الجلسة وإنشائها. |
| expires_at | TIMESTAMP | - | لا (NOT NULL) | تاريخ ووقت انتهاء صلاحية الجلسة تلقائياً. |
| revoked_at | TIMESTAMP | - | نعم (NULL) | تاريخ ووقت إلغاء الجلسة يدوياً عند تسجيل الخروج أو الإيقاف؛ وتبقى القيمة فارغة ما دام الجلسة نشطة. |

## جدول المشرفين (Admins)

يحدد هذا الجدول المستخدمين الذين يمتلكون صلاحيات إدارية وتاريخ منحهم هذه الصلاحية.

| اسم الحقل | نوع البيانات | القيود والمفاتيح | يقبل فارغاً؟ | الوصف الوظيفي |
|---|---|---|---|---|
| id | INTEGER | مفتاح أساسي (PK)، يُنشأ تلقائياً | لا (NOT NULL) | المعرف الرقمي الفريد لسجل المشرف. |
| user_id | INTEGER | FK يشير إلى `Users(id)`، UNIQUE | لا (NOT NULL) | يربط المستخدم بحساب المشرف ويضمن عدم تكرار الصلاحية لنفس المستخدم. يحمل القيد اسم `fk_Admins_user_id_Users`. |
| is_admin | BOOLEAN | - | لا (NOT NULL) | قيمة منطقية تحدد ما إذا كانت صلاحية المشرف مفعّلة حالياً. |
| assigned_at | TIMESTAMP | - | لا (NOT NULL) | تاريخ ووقت تعيين المستخدم كمشرف ومنحه الصلاحية. |
