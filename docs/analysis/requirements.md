# متطلبات المشروع
## AuthKit

## 1. المتطلبات الوظيفية (Functional Requirements)

| الرمز | المتطلب |
|---|---|
| FR-01 | يجب أن يتيح النظام إنشاء حساب مستخدم جديد باستخدام بيانات التسجيل المعتمدة. |
| FR-02 | يجب أن يتيح النظام للمستخدم تسجيل الدخول والتحقق من بيانات اعتماده. |
| FR-03 | يجب أن يتيح النظام للمستخدم تسجيل الخروج وإنهاء جلسته. |
| FR-04 | يجب أن يتيح النظام استرجاع بيانات المستخدم الحالي المرتبط بالجلسة. |
| FR-05 | يجب أن يتيح النظام التحقق من صلاحية جلسة المستخدم. |
| FR-06 | يجب أن يدعم النظام التمييز بين كيان User وكيان Admin وفق تصميم البيانات المعتمد. |

> ملاحظة: تفاصيل حقول الطلبات والاستجابات، وأكواد HTTP، وآلية المصادقة ستحدد في وثيقة تصميم REST API. ولا يعني وجود كيان Admin أن الإصدار الأول يتضمن واجهات أو مسارات عامة لإدارة المديرين.

## 2. المتطلبات غير الوظيفية (Non-Functional Requirements)

- **Security:** حماية بيانات الاعتماد، وعدم تخزين كلمات المرور بصيغتها الأصلية، واستخدام آلية آمنة لتجزئتها.
- **Reusability:** تصميم Backend وSDK بحيث يمكن دمجهما في مشاريع مختلفة دون الاعتماد على تطبيق واحد.
- **Maintainability:** تنظيم المكونات وفصل المسؤوليات لتسهيل الصيانة والتطوير.
- **Testability:** تصميم المكونات بما يسمح باختبارها بصورة مستقلة واختبار التكامل بينها.
- **Usability:** توفير واجهة SDK واضحة وبسيطة للمطور الذي سيستخدم الميزة.
- **Consistency:** توحيد طريقة التعامل مع نتائج العمليات والأخطاء عبر واجهات النظام.

## 3. حالات الاستخدام (Use Cases)

### UC-01: إنشاء حساب (Sign Up)

- **الممثل:** User.
- **الهدف:** إنشاء حساب جديد في النظام.
- **النتيجة المتوقعة:** إنشاء الحساب وحفظ بياناته بعد التحقق من صحة المدخلات وعدم تعارضها مع حساب موجود.
- **المسار المرتبط:** `POST /auth/signup`.

### UC-02: تسجيل الدخول (Sign In)

- **الممثل:** User.
- **الهدف:** التحقق من بيانات المستخدم وبدء جلسة استخدام.
- **النتيجة المتوقعة:** قبول بيانات الاعتماد الصحيحة وإنشاء جلسة وفق آلية الجلسات التي سيعتمدها التصميم.
- **المسار المرتبط:** `POST /auth/signin`.

### UC-03: تسجيل الخروج (Sign Out)

- **الممثل:** User.
- **الهدف:** إنهاء جلسة المستخدم الحالية.
- **النتيجة المتوقعة:** إنهاء الجلسة بحيث لا تعود صالحة للاستخدام.
- **المسار المرتبط:** `POST /auth/signout`.

### UC-04: جلب المستخدم الحالي (Get Current User)

- **الممثل:** User.
- **الهدف:** معرفة هوية المستخدم المرتبط ببيانات الجلسة الحالية.
- **النتيجة المتوقعة:** إرجاع بيانات المستخدم الحالي عند وجود جلسة صالحة.
- **المسار المرتبط:** `GET /auth/me`.

### UC-05: التحقق من الجلسة (Validate Session)

- **الممثل:** التطبيق المستفيد أو User من خلاله.
- **الهدف:** التحقق من صلاحية جلسة الاستخدام.
- **النتيجة المتوقعة:** إرجاع نتيجة واضحة توضح ما إذا كانت الجلسة صالحة.
- **المسار المرتبط:** `GET /auth/validate`.
